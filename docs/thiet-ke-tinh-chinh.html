1. Đánh Giá Khách Quan & Định Hướng Tinh Chỉnh
Tại sao cần tinh chỉnh lại bản thiết kế gốc?

Bản thiết kế ban đầu trong README mang tầm vóc một hệ thống thương mại cấp doanh nghiệp (25 bảng, 117 Stored Procedures, các quy trình tranh chấp đa cấp). Điều này vượt quá 400% yêu cầu đồ án, gây áp lực bảo trì CSDL cực lớn và gây rủi ro thất bại khi triển khai lên các dịch vụ Free Hosting (do hosting miễn phí chặn quyền tạo procedure phức tạp hoặc không cho chạy CLI Cronjob). Bản tinh chỉnh này đưa đồ án về đúng điểm rơi hoàn hảo: Vừa đủ vượt chuẩn để lấy điểm tối đa, vừa tinh gọn để làm chủ 100% mã nguồn.

2. Kiến Trúc Backend OOP + MVC Tinh Gọn

Hệ thống áp dụng mô hình Front Controller + Custom MVC viết bằng PHP 8 thuần theo chuẩn OOP, không dùng framework nặng nề để giảng viên thấy rõ năng lực lập trình hướng đối tượng của nhóm:

Controller Layer

Tiếp nhận Request từ Front Controller (`Router`), xác thực quyền (`Middleware`), gọi Service xử lý và điều phối trả về HTML View hoặc JSON Response (cho AJAX).

Service Layer

Chứa toàn bộ logic nghiệp vụ (Tính giá tour, tích hợp MoMo Sandbox, đọc OpenWeather JSON, phân tích XML RSS). Đảm bảo Controller không bị phình to (Fat Controller).

Model & PDO Layer

Thực thi truy vấn và gọi 22 Stored Procedures qua PDO Prepared Statements. Bảo vệ ứng dụng tuyệt đối khỏi lỗi bảo mật SQL Injection.

Cấu trúc cây thư mục chuẩn hóa trong codebase:

4. Danh Mục 22 Stored Procedures Cốt Lõi (Đủ ≥ 20 Yêu Cầu)
Tiết kiệm 80% công sức lập trình: Thay vì viết 117 procedure tràn lan cho cả những thao tác SELECT tầm thường, nhóm tập trung toàn lực vào 22 Procedures quan trọng nhất. Toàn bộ các thao tác nghiệp vụ phức tạp (khóa chỗ đồng thời, áp dụng thanh toán, xử lý hoàn tiền, duyệt tour) đều được thực thi nguyên tử trong CSDL.
Phân hệ TV1: Users & Categories (5 SPs)

File: database/procedures/01_users_categories.sql

  1. sp_users_register(p_email, p_name, p_hash, p_phone): Đăng ký Tourist mới.
  2. sp_users_find_login(p_email): Lấy thông tin xác thực để PHP verify password.
  3. sp_users_update_profile(p_user_id, p_name, p_phone): Cập nhật hồ sơ cá nhân.
  4. sp_users_set_status(p_admin_id, p_user_id, p_status): Admin khóa/mở tài khoản.
  5. sp_categories_save(p_admin_id, p_id, p_name, p_slug, p_desc, p_icon): Thêm/sửa danh mục.
Phân hệ TV2: Tour & Sức Chứa (6 SPs)

File: database/procedures/02_services_bookings.sql

  1. sp_services_create(p_host_id, p_cat_id, p_title, p_mode, p_price, ...): Host tạo tour.
  2. sp_services_update(p_host_id, p_id, p_title, p_desc, ...): Host cập nhật thông tin tour.
  3. sp_services_moderate(p_admin_id, p_id, p_status): Admin duyệt tour mở bán.
  4. sp_accommodations_save(p_host_id, p_service_id, p_hotel, ...): Thiết lập lưu trú.
  5. sp_schedules_create(p_host_id, p_service_id, p_starts, p_ends, p_cap): Mở lịch khởi hành.
  6. sp_schedules_cancel(p_host_id, p_schedule_id, p_reason): Host hủy lịch có hoàn tiền.
Phân hệ TV3: Booking & MoMo (6 SPs)

File: database/procedures/03_promotions_payments.sql

  1. sp_bookings_quote(p_schedule_id, p_count, p_plan): Tính tổng tiền & giảm giá.
  2. sp_bookings_create(p_tourist_id, p_schedule_id, p_count, ...): Tạo booking pending.
  3. sp_bookings_approve(p_host_id, p_booking_id): Host duyệt giữ chỗ có hạn 15 phút.
  4. sp_bookings_cancel(p_actor_id, p_booking_id, p_reason): Hủy chỗ & nhả capacity.
  5. sp_payments_apply_verified(p_booking_id, p_order_id, p_amount, ...): Áp dụng IPN MoMo thành công, confirmed booking.
  6. sp_refunds_create_and_approve(p_admin_id, p_payment_id, p_amount, ...): Admin duyệt lệnh hoàn tiền.
Phân hệ TV4: Cộng Đồng & Blog (5 SPs)

File: database/procedures/04_community_content.sql

  1. sp_discussions_create(p_user_id, p_service_id, p_parent_id, p_msg): Bình luận hỏi đáp.
  2. sp_reviews_create(p_tourist_id, p_booking_id, p_rating, p_comment): Đánh giá tour.
  3. sp_posts_save(p_admin_id, p_id, p_title, p_slug, p_content, p_thumb): Viết/sửa bài blog.
  4. sp_posts_delete(p_admin_id, p_id): Xóa bài blog du lịch.
  5. sp_promotions_save(p_admin_id, p_id, p_code, p_title, p_percent, ...): Tạo mã giảm giá.

Định dạng JSON & AJAX

6. Phân Hệ Quản Trị Admin Chuẩn Mực (Không Lan Man)

Bám sát chỉ đạo đề bài: "Phần quản trị, chỉ cần dừng ở mức cơ bản (Thêm được danh mục, sản phẩm, bài viết, v.v.)". Admin tập trung vào 5 màn hình CRUD rõ ràng:

1. Quản lý Danh mục
Xem danh sách, thêm danh mục mới, chỉnh sửa tên/mô tả/icon, ẩn danh mục không sử dụng.
2. Quản lý & Duyệt Tour
Xem danh sách tất cả các tour do Host đăng lên, bấm duyệt (Approved) hoặc từ chối (Rejected) trước khi mở bán công khai.
3. Quản lý Bài viết (Blog)
Viết bài chia sẻ kinh nghiệm du lịch, chỉnh sửa nội dung, upload ảnh đại diện và đăng tải/xóa bài viết.
4. Quản lý Mã giảm giá
Tạo coupon khuyến mãi (ví dụ: `HE2026` giảm 10%), đặt ngày bắt đầu và kết thúc.
5. Thống kê Booking & Users
Xem danh sách đặt chỗ trên toàn hệ thống (Pending, Confirmed, Cancelled) và khóa tài khoản vi phạm nếu cần.
7. Chiến Lược Triển Khai Tuyệt Đối An Toàn Trên Free Hosting
Cảnh giác các cạm bẫy của Free Hosting (InfinityFree, 000webhost, ByetHost...)
  • Free Hosting KHÔNG hỗ trợ SSH / Terminal: Do đó tuyệt đối không thiết kế các script CLI chạy nền bắt buộc.
  • Free Hosting thường giới hạn quyền CSDL SUPER / DEFINER: Do đó toàn bộ 22 Procedure đều được viết cú pháp tiêu chuẩn MySQL 8 / MariaDB, không dùng DEFINER đặc quyền.
  • Giải pháp Lazy Expiration: Thay vì cần một cronjob chạy mỗi 1 phút để hủy các booking quá 15 phút chưa thanh toán, ta xử lý tự động ngay khi có người dùng truy cập trang danh sách hoặc chi tiết booking (Query UPDATE trạng thái các record hết hạn trước khi SELECT).
Quy trình Deploy nhanh lên Free Hosting (cPanel / DirectAdmin):
  1. Nén thư mục dự án (ngoại trừ .git và config/local.php) thành file .zip.
  2. Upload lên thư mục htdocs/ hoặc public_html/ của hosting.
  3. Tạo MySQL Database trên cPanel, import lần lượt schema.sql, 4 file procedures và seed_data.sql bằng phpMyAdmin.
  4. Tạo file config/local.php trên File Manager với thông số DB vừa tạo. Trang web sẽ chạy ngay lập tức!
